# Outliner shell (Tauri 2)

A desktop + Android shell around this repo's **existing** web build. It wraps
`apps/web/dist` as-is; it does not touch `apps/web` or `packages/`.

- Product name: **Outliner**
- Identifier: **`dev.outliner.app`** (same as the old Capacitor shell)
- Phase 1 of the native-app work: TypeScript/HTML under a native shell. The
  Rust/GPUI rewrite is a separate track.

> **This directory is not an npm workspace.** The root `package.json` has
> `"workspaces": ["packages/*", "apps/*", "!apps/shell"]`. Without that
> negation, npm treats `apps/shell` as a workspace and `npm ci` at the root
> fails with `EUSAGE: Missing: outliner-shell@0.1.0 from lock file` — which
> would break the existing `ci` workflow. Do not remove the `!apps/shell`
> entry, and keep this directory's `package.json`/`package-lock.json`
> self-contained.
>
> `apps/web/dist` is gitignored, so **build the web app before the shell**:
> `npm run build -w @outliner/web` at the repo root.

## 1. What is verified, and where

This machine is **Linux/aarch64 with no GPU and no Xcode**, so the build matrix
is not symmetric. Read this before trusting anything below.

| Target | Status here | How it was judged |
|---|---|---|
| Linux desktop (`cargo build`, debug + release) | **verified** | compiles; release `tauri build` makes `.deb` + `.AppImage`; headless smoke test boots the real web build |
| Linux desktop window + web app boot | **verified** | `scripts/smoke-linux.sh`: window 1200x820 exists, webview reports `document.title = "Welcome — Outliner"` and the welcome document rendered |
| Menu → web command dispatch | **verified** | `scripts/smoke-menu.sh`: `Mod+,` opens the settings dialog, `Mod+/` opens the shortcuts panel |
| Menu/keymap drift | **verified** | `scripts/smoke-menu-keys.sh`: all 12 combos the menu can send are present in the app's own generated shortcut table (negative control: renaming one to `Mod+Shift+Q` makes it fail) |
| File downloads (backup / export) | **verified** | a `<a download href="blob:">` probe wrote a real file with the right contents |
| External links leave the app | **verified (dispatch only)** | `scripts/smoke-links.sh`: `window.open`/`target="_blank"` are intercepted, in-app URLs are not, the app does not navigate away. The OS hand-off itself cannot be observed here (no browser installed). |
| Android APK (all 4 ABIs) | **verified to build** | release APK builds; `scripts/android-verify.sh` checks manifest, per-ABI ELF, JNI exports, 16 KB alignment, embedded web build |
| Android app actually running | **not verified** | no `/dev/kvm` → no emulator. Needs a real device. |
| **macOS build** | **not verified here — CI does it** | no `xcodebuild` on Linux. `macos` job in `.github/workflows/shell.yml` builds the universal `.app`/`.dmg` on a `macos-15` runner. See §6. |
| macOS menu bar behaviour | **partially** | the menu-building and dispatch code is `#[cfg(desktop)]`, so it compiles and runs on Linux (GTK menu bar) and the *dispatch* path is tested. The AppKit-specific look and the real Cmd accelerator handling are untested. |
| Korean IME inside the shell | **not verified** | needs a real macOS/Android input method. This shell uses the system webview's own IME, which is the browser-supported path. |
| Signing | **ad-hoc only** | `signingIdentity: "-"`, so Gatekeeper shows the "unidentified developer" prompt, not "damaged". Not notarized. See §4. |

Screenshots were deliberately **not** used as evidence: this box runs Xvfb with
no GPU, so pixel capture comes out black. The checks above are behavioural.

## 2. Layout

```
apps/shell/
├── VERIFY.log                   # captured output of every check in §1
├── package.json                 # @tauri-apps/cli only; no frontend build step
├── scripts/
│   ├── android-env.sh           # source me: NDK/JDK/PATH for Android builds
│   ├── android-verify.sh        # APK static verification
│   ├── doctor.sh                # what this machine can and cannot build
│   ├── smoke-links.sh           # external links leave the app, in-app links do not
│   ├── smoke-linux.sh           # headless boot test for the desktop shell
│   ├── smoke-menu.sh            # menu-item → web-command dispatch test
│   └── smoke-menu-keys.sh       # every menu combo still matches a live keymap binding
└── src-tauri/
    ├── Cargo.toml               # lib (mobile) + bin (desktop)
    ├── build.rs                 # tauri-build + Android 16 KB page alignment
    ├── tauri.conf.json          # window, identifier, frontendDist, bundles
    ├── tauri                    # shim the generated Gradle project invokes
    ├── capabilities/default.json
    ├── icons/                   # generated from apps/web/dist/icon.svg
    ├── src/
    │   ├── main.rs              # desktop entry point
    │   └── lib.rs               # shared run(), navigation, menu
    └── gen/android/             # generated by `tauri android init`; kept in tree
```

`frontendDist` is `../../web/dist`, i.e. `apps/web/dist` — resolved relative to
`src-tauri/`. The shell never writes there; it only reads the built assets.

## 3. Building on Linux (the target that is verified here)

### Prerequisites

```sh
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev libsoup-3.0-dev \
                 libjavascriptcoregtk-4.1-dev librsvg2-dev patchelf
```

`scripts/doctor.sh` reports anything missing.

### Build

```sh
# from the repo root: the web build is what the shell embeds
npm ci
npm run build -w @outliner/web

cd apps/shell
npm ci
cargo build --manifest-path src-tauri/Cargo.toml        # debug
npx tauri build                                        # release + .deb/.AppImage
```

Output: `src-tauri/target/release/outliner` and
`src-tauri/target/release/bundle/{deb,appimage}/`.

### Verify without a display

WebKitGTK needs a session bus, and the app needs an X server. Under Xvfb:

```sh
DISPLAY=:99 ./scripts/smoke-linux.sh     # boots the web build, checks the DOM
DISPLAY=:99 ./scripts/smoke-menu.sh      # checks menu-item dispatch
DISPLAY=:99 ./scripts/smoke-links.sh     # checks external-link interception
DISPLAY=:99 ./scripts/smoke-menu-keys.sh # checks every menu combo is a live binding
```

All four fail loudly rather than silently passing, and each has a negative
control that was actually exercised:

| script | negative control that was verified to fail |
|---|---|
| `smoke-linux.sh` | point `frontendDist` at a directory with no `index.html` → `FAIL: '#app .app' not found` |
| `smoke-menu-keys.sh` | rename one combo to `Mod+Shift+Q` → `FAIL: … is not in the app's shortcut table` |
| `smoke-menu.sh` | asserts on overlay text, not just element counts |
| `smoke-links.sh` | asserts an *internal* link is **not** prevented, so a blanket block would fail |

The eval hook these tests use is compiled into the shell on purpose: with no
GPU, asking the webview what it rendered is the only honest check available.
It only runs when `OUTLINER_SMOKE_EVAL` is set.

## 4. Building on macOS

Two ways: **CI** (below and §6) does it for you, or build locally on a Mac.
The dev box this shell was written on has no Xcode, so neither path has been
run there — CI is the one that actually produces the .dmg.

```sh
xcode-select --install          # once
rustup target add aarch64-apple-darwin x86_64-apple-darwin

# from the repo root
npm ci
npm run build -w @outliner/web

cd apps/shell
npm ci
npx tauri build
```

Output:
- `src-tauri/target/release/bundle/macos/Outliner.app`
- `src-tauri/target/release/bundle/dmg/Outliner_0.1.0_<arch>.dmg`

Universal binary (Apple Silicon + Intel):

```sh
npx tauri build --target universal-apple-darwin
```

### What to check on the Mac

1. The window opens at 1200×820 and the welcome document renders.
2. **Cmd** shortcuts work (`Cmd+,` settings, `Cmd+/` shortcuts, `Cmd+Z` undo).
   The web keymap derives `Mod` from `navigator.platform` matching `/Mac/`,
   which is true in WKWebView, so no shell work is needed — but confirm it.
3. The menu bar items dispatch. They send a synthetic `keydown` with
   `metaKey` (see `forward_combo` in `src-tauri/src/lib.rs`); a menu item that
   does nothing means the combo string drifted from
   `apps/web/src/editor/keymap.ts`.
4. Korean IME composition in the editor.
5. External links from the share dialog open in Safari, not inside the app.

### Signing / notarization

The app is **ad-hoc signed**, not properly signed:

```json
"bundle": { "macOS": { "signingIdentity": "-" } }
```

That is deliberate. On Apple Silicon, an app with *no* signature at all is
reported by macOS as **"damaged and can't be opened"** — and `xattr` does not
reliably fix that. An ad-hoc signature downgrades it to the normal
"unidentified developer" prompt, which the user can get past:

```sh
# either: right-click Outliner.app > Open, then "Open" again
# or:
xattr -d com.apple.quarantine /Applications/Outliner.app
```

It is **not notarized**, so the prompt appears for every download. To remove it
you need a paid Apple Developer account (Developer ID Application certificate +
notarization credentials). See `.github/workflows/shell.yml`, "Enabling
signing", for exactly where those secrets go.

## 5. Building for Android

### Prerequisites

- Android SDK with **platform 37** and **build-tools 37.0.0**
  (`compileSdk`/`targetSdk` = 37 come from the generated Gradle project;
  `minSdk` = 24)
- NDK r27 (`ANDROID_NDK_HOME`)
- JDK 17

```sh
cd apps/shell
source scripts/android-env.sh      # sets ANDROID_HOME/NDK_HOME/JAVA_HOME/PATH

npx tauri android init             # already done; regenerates gen/android
npx tauri android build --apk                  # release, unsigned
npx tauri android build --debug --apk          # debug, signed with the debug key
./scripts/android-verify.sh <path-to.apk>      # static checks
```

Outputs (all under `src-tauri/gen/android/app/build/outputs/apk/universal/`):

| Build | Size | ABIs |
|---|---|---|
| `release/…-release-unsigned.apk` | **26 MB** | all 4 |
| `debug/…-debug.apk` | **493 MB** | all 4 (debug symbols kept) |
| `release/…` with `--target aarch64` | **7.7 MB** | arm64 only |

For shipping, build only the ABI you need:

```sh
npx tauri android build --apk --target aarch64    # 7.7 MB
```

The 4-ABI release APK is only 26 MB even though every ABI embeds the whole web
build (`apps/web/dist` is 3.0 MB; the CSS/JS/fonts compress well). arm64-only is
what you would actually upload.

### Installing on a device

```sh
# Debug build: signed with the debug key, installs directly.
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
```

An **unsigned release APK will not install.** Signing is not configured here on
purpose: there is no production keystore in this repo, and generating one and
committing it would be a security mistake.

Tauri 2 has no signing section in `tauri.conf.json` for Android; signing is
plain Gradle. Create a keystore, then add a `signingConfigs` block to
`src-tauri/gen/android/app/build.gradle.kts` and reference it from the
`release` build type:

```sh
keytool -genkeypair -v -keystore ~/outliner-release.jks \
  -keyalg RSA -keysize 4096 -validity 10000 -alias outliner
```

```kotlin
// src-tauri/gen/android/app/build.gradle.kts
android {
    signingConfigs {
        create("release") {
            storeFile = file(System.getenv("OUTLINER_KEYSTORE") ?: "/path/outliner-release.jks")
            storePassword = System.getenv("OUTLINER_KEYSTORE_PASSWORD")
            keyAlias = "outliner"
            keyPassword = System.getenv("OUTLINER_KEY_PASSWORD")
        }
    }
    buildTypes {
        getByName("release") {
            signingConfig = signingConfigs.getByName("release")
        }
    }
}
```

Keep passwords in environment variables (or CI secrets) and the keystore out of
git — losing the keystore blocks future Play Store updates permanently.
Note that `src-tauri/gen/android/` is generated by `tauri android init`, so if
you ever re-run `init` the edit is lost; a `.patch` applied in CI is the stable
option.

### Two things that will bite you

1. **16 KB page alignment.** Android 15 shipped 16 KB-page devices; a 4 KB
   aligned `.so` fails to load there. NDK r27 still links 4 KB by default, so
   `build.rs` emits `-Wl,-z,max-page-size=16384`. It has to be in `build.rs`
   because the Tauri CLI exports `CARGO_TARGET_<TRIPLE>_RUSTFLAGS`/`_LINKER`,
   which override `.cargo/config.toml`. Verified: every ABI reports `0x4000`.
2. **Cleartext HTTP for a self-hosted server.** `release` builds set
   `usesCleartextTraffic=false`, so an `http://` server URL entered in Settings
   will be refused; `https://` works. The old Capacitor config had
   `cleartext: true`. If you want to allow plain HTTP to a LAN server, flip
   `manifestPlaceholders["usesCleartextTraffic"]` in
   `src-tauri/gen/android/app/build.gradle.kts` — it is off here because
   shipping an app that silently permits cleartext is worse than a clear error.

## 6. CI (GitHub Actions)

`.github/workflows/shell.yml` builds the shell on GitHub's runners, which is how
the macOS build happens at all. It runs on pushes and PRs that touch
`apps/shell`, `apps/web`, `packages` or the workflow itself, and on manual
dispatch.

| job | runner | produces | artifact name |
|---|---|---|---|
| `macos` | `macos-15` (Apple Silicon) | universal `.app` + `.dmg` | `outliner-macos-dmg`, `outliner-macos-app` |
| `linux` | `ubuntu-24.04` | `.deb` + `.AppImage` | `outliner-linux` |
| `android` | `ubuntu-24.04` | arm64 debug `.apk` | `outliner-android-apk` |

The jobs are independent (no `needs:`), so a macOS failure still lets you read
the Android result. Artifacts are kept 14 days.

Each job verifies its own output instead of trusting the exit code:

- **macos** — the bundle exists, the executable is a Mach-O with both slices
  (`lipo -archs`), `Info.plist` lints, `CFBundleIdentifier` is
  `dev.outliner.app`, and a `.dmg` was produced.
- **linux** — the binary runs, and the web build is embedded inside it
  (`strings` finds `assets/index-*.js`), which catches a missing web build.
- **android** — `aapt2` reports the right package/minSdk/targetSdk, the APK is
  16 KB-page aligned, and it is signed (debug key) so `adb install` works.

Ordering that matters: every job runs `npm ci && npm run build -w @outliner/web`
**before** the shell build. `apps/web/dist` is gitignored, so without this step
Tauri fails with `Unable to find your web assets`.

### Downloading and running what CI made

1. Open the workflow run, download `outliner-macos-dmg`, unzip, drag
   `Outliner.app` to `/Applications`.
2. First launch: right-click > **Open**, or
   `xattr -d com.apple.quarantine /Applications/Outliner.app` (see §4).
3. Android: `adb install -r app-universal-debug.apk`.

### What CI cannot tell you

CI proves the build and the bundle structure. It does **not** prove the app
works: no window is opened, no key is pressed. Still needs a human on a Mac:

- Korean IME composition in the editor
- **Cmd** shortcuts and the menu bar actually dispatching (§4 checklist)
- External links opening in Safari

## 7. What this machine could not do, and why

Recorded so the next person does not re-derive it.

### The Android SDK/NDK is x86-64 and this host is aarch64

Google dropped aarch64 **Linux** NDK support in r23. Every NDK/SDK binary here
is an x86-64 ELF, so `aapt2`, `zipalign` and the NDK's `clang` die with
`Exec format error`.

Fix applied on this machine (not part of the project, and not needed on a
normal x86-64 Linux box or a Mac):

```sh
sudo apt install qemu-user-static          # registers the binfmt handler
# then install an x86-64 glibc + loader, since binfmt needs /lib64/ld-linux-x86-64.so.2
# (packages: libc6, libstdc++6, libgcc-s1, zlib1g for amd64)
```

After that the real NDK toolchain runs unmodified, which is why this project
uses `linker = "aarch64-linux-android24-clang"` rather than the host-clang +
sysroot shim that the GPUI spike needed. Both work; this one is closer to what
the NDK and AGP expect.

`scripts/doctor.sh` detects this and prints the fix if the loader is missing.

### The generated Gradle project invokes `node tauri`

`RustPlugin.kt` (generated) runs `node tauri android android-studio-script`
with `src-tauri` as its working directory, so Node resolves `tauri` as a *file
path* relative to `src-tauri`. `src-tauri/tauri` is a two-line ESM shim that
loads the real CLI. Without it every `tauri android build` fails with
`Cannot find module '.../src-tauri/tauri'`.

### `tauri android init` needs `compileSdk 37`

The generated project asks for 37. Installed via
`sdkmanager "platforms;android-37.0" "build-tools;37.0.0"`.

## 8. Design decisions in the shell

**The web app is the source of truth for commands.** Menu items do not
re-implement behaviour; they dispatch a synthetic `keydown` matching the web
keymap (`apps/web/src/editor/keymap.ts`). That keeps one definition of "undo",
and means a menu item cannot silently do something different from the shortcut.
The trap: `comboOf()` maps `Mod` to **only** `metaKey` on macOS and **only**
`ctrlKey` elsewhere, and treats `metaKey+ctrlKey` on macOS as `Mod+Ctrl+...`.
`MOD_JS` in `src-tauri/src/lib.rs` follows that exactly.

**External links leave the app.** Two mechanisms, both shell-side:

1. A plugin `on_navigation` hook allows `tauri://`, `about:`, `blob:`, `data:`
   and `tauri.localhost`, and sends everything else to the OS.
2. A document-start init script replaces `window.open` for external URLs and
   cancels `target="_blank"` anchor clicks. This is needed because neither
   WKWebView nor WebKitGTK opens a browser window on its own — `window.open`
   just returns `null` — and the Android WebView has multiple-window support
   off. Without it, "open in new tab" and the share dialog's Open button are
   dead controls with no error anywhere.

In-app URLs (`tauri:`, `#hash` routes) are deliberately left alone; verified by
`scripts/smoke-links.sh` that an internal link is *not* prevented.

**IndexedDB lives under the identifier.** Data is at
`~/.local/share/dev.outliner.app/databases/indexeddb` (Linux). Because the
identifier matches the old Capacitor app's `appId`, the app identity is
consistent, but **Capacitor's WebView storage is a different directory** — an
existing Android install will not see its old data. Export/import through the
app's backup feature when migrating. Verified here that the shell writes
`doc:` records durably (2 records after one boot).

**No JS API layer.** `withGlobalTauri` is off and the capability set is
`core:default` + `opener:default`. The web build does not call Tauri APIs, so
there is nothing to expose. This keeps the shell's attack surface minimal and
means the web build is unchanged.

**Consequences of the `tauri://localhost` origin** (measured, not assumed):

| Feature | In the shell |
|---|---|
| IndexedDB / localStorage | works; durable across restarts (verified) |
| File download (backup/export/Markdown) | works — `<a download href="blob:">` writes the file to the cwd/home (verified: a probe file appeared with the right contents). The web app's backup and export paths rely on this. |
| Service worker | **does not register** — `tauri:` is not an http(s) scheme, so `navigator.serviceWorker.register` throws. Not a problem (assets are bundled, nothing to cache) but it means no offline-update path through the SW. |
| `Capacitor.isNativePlatform()` | `false`. The web build's native branch (`apps/web/src/platform.ts`: Android back button, system-bar styling, the `native` CSS class) **does not run**. |
| Android hardware back button | handled by Tauri's own `AppPlugin`: if no JS listener is registered (and none is, since `platform.ts` never runs) it calls `webView.goBack()` when possible, else `activity.onBackPressed()`. So back walks the **WebView history** — which includes `#hash` route changes — and exits when there is none. Consequence: a back press may pop one route step instead of closing an open dialog. Needs a device check; fixing it properly means registering a `back-button` listener, which is web-side work. |
| Share-link URLs (`itemUrl()`) | built from `location.origin`, so they read `tauri://localhost/#d=…`. Fine inside the app; **not shareable** with another person. Uses `navigator.clipboard`, which is allowed on this origin. |
| `#`-route navigation, back/forward | works (hash changes, no page loads) |

The two items that need a decision are the Android back button and share links;
both are web-side concerns, and this work is explicitly not allowed to change
web code. Flagged in `task.md` rather than fixed here.

## 9. Troubleshooting

| Symptom | Cause |
|---|---|
| App starts, 10x10 window, `setup` never logs, no WebKit child process | No D-Bus session. WebKitGTK waits on `xdg-desktop-portal`. Run under `dbus-run-session`. |
| `libEGL warning: failed to open /dev/dri/...` | No GPU (expected here). Harmless: WebKit falls back to software rendering. |
| `Cannot find module '.../src-tauri/tauri'` | `src-tauri/tauri` shim missing. |
| `Exec format error` from NDK/SDK tools | aarch64 host + x86-64 tools; see §7. |
| `'.so' has unexpected e_machine` / fails to load on a phone | Wrong ABI, or 4 KB alignment; run `scripts/android-verify.sh`. |
| Menu item does nothing | Combo string drifted from the web keymap; run `scripts/smoke-menu.sh`. |
| Android app shows no data after switching from Capacitor | Different WebView storage directory; import a backup. |
